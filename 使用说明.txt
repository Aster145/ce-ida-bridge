CE ↔ IDA 自动校准（Windows / Eden、Ryujinx / ARM64）

实际流程
CE 运行脚本 → IDA 命中你设置的代码断点 → IDA 自动导出附近字节 → CE 自动 AOB 搜索 → 自动列出差值。
不再需要手动复制内存字节或计算加减。

首次加载
1. 在 IDA 中通过 Remote GDB debugger 连接模拟器设置的端口。
   当前 Eden 配置示例：127.0.0.1:6543。端口只在 IDA 中设置，脚本无需修改。
2. IDA 菜单 File → Script file（通常 Alt+F7），选择 ida_ce_bridge.py。
   Output 窗口应显示 “[CE-IDA] 已就绪”。脚本读取运行时内存，不用静态 IDB 字节。
3. CE 选择正在运行该游戏的 Eden 或 Ryujinx 进程。
4. 双击 CE_IDA自动校准.CT，允许执行其中的 Lua 脚本，会弹出工具窗口。
   也可在 CE 的 Memory View → Tools → Lua Engine 中打开 ce_ida_bridge.lua 并执行。
5. 回到 IDA，在 ARM64 程序代码上按 F2 下一个执行断点，F9 继续，让它命中。
   命中后保持暂停。CE 会自动搜索，窗口中显示 IDA 参考地址、CE 对应地址和映射差值。

IDA 中的 Python 脚本只需每次打开 IDA 后加载一次。
如果加载脚本时游戏已经暂停，它会立即导出当前 PC 附近的样本。
如果样本比 CE 工具更早生成，点击 CE 工具的“搜索最近样本”即可。

换算金钱 / 血量地址
先在 CE 正常搜索数值，获得 CE 地址，再填到工具的“CE 金钱 / 血量地址”。
点击“换算游戏地址”，然后“复制游戏地址”，在 IDA 调试内存窗口中跳转查看。
公式：Δ = CE参考地址 − 游戏参考地址；游戏目标地址 = CE目标地址 − Δ。

出现多个 AOB 命中
模拟器可能存在镜像映射或内存副本。工具显示全部候选，不擅自采用第一个。
在下拉框选择某个 CE 命中地址，再换算金钱地址；在 IDA 中对比目标值和附近字节。
参考代码与金钱地址必须属于使用同一差值的映射。单凭一个代码 AOB 命中不能证明堆地址一定适用。

未找到匹配
确认 CE 选择的是 IDA 当前调试游戏所在的 Eden / Ryujinx 进程。
CE 扫描设置中应启用 MEM_MAPPED（映射内存）的扫描；来宾代码可能位于 Windows 非可执行页。
脚本不按 Windows 的 Executable / Writable 标志缩小范围。
换一个实际执行的 ARM64 代码断点重试，取样区域不要再放其他断点。
工具从断点后 +4 字节开始取样，避开当前 ARM64 软件断点的指令字节。
搜索全进程可能需要一段时间，期间不要切换 CE 进程。

手动重发 / 停止
IDA Python 控制台输入 ce_ida_export_now()：从当前暂停线程的 PC 附近重新导出。
输入 ce_ida_stop()：停止自动导出。重新执行 ida_ce_bridge.py 可恢复。
关闭 CE 工具窗口可停止自动接收；若正在扫描，等待它完成再关闭。

运行方式
IDA 和 CE 必须运行在同一 Windows 用户环境中。
两个脚本通过 %TEMP%\CE_IDA_Bridge\anchor.txt 交换样本，只写这份临时样本文件。
CE 不连接 GDB 端口，因此不会占用 IDA 已建立的 GDB 连接。
程序不替你选择或设置断点，不自动继续执行游戏，也不修改游戏内存。
每次重启游戏或模拟器后，需要重新命中断点校准。
在同一时间只使用一个 IDA / 模拟器校准会话。
